# M2-PERF-CI 设计补洞（LOCK 前 DRAFT 文档）

### 1) 场景清单（可执行）

1. **场景一：Idle（闲置零开销）**
    * *步骤*：启动应用并保持静止不进行任何交互，持续采集 $\ge 1000$ 帧以检测静态背景下的 CPU/GPU 额外占用。
2. **场景二：Steady Play（平稳动画播放）**
    * *步骤*：连续加载并循环播放标准卡片展开 token 动画，持续采集 $\ge 1000$ 帧。
3. **场景三：Interrupted Retarget（中途打断重定向负载）**
    * *步骤*：在弹簧动画运行中途高频触发连续打断与反向重定向（承接 M2-02 smoke），持续采集 $\ge 1000$ 帧。

### 2) 每场景帧数 / 轮次（写死建议）

* **每场景帧数**：严格 $\ge 1000$ 帧。
* **每机轮次 / 独立进程**：每场景在独立进程中独立运行 $\ge 2$ 轮。
* **硬件机台合规规则**：两台物理机（$\ge 2$ 台）均须严格运行同一场景集；仅 1 台物理机或使用虚拟机凑数直接判为 **INVALID**。

### 3) P95 / P99 目标句（一句可执行）

* **P95 目标**：UI 线程框架部分、渲染阶段、GPU 阶段在相对刷新间隔 $T$ 的周期占比内分别不超过 $12\%$、$35\%$、$35\%$，且相对本机基线回退 $\le 10\%$。
* **P99 目标**：每千帧丢帧率（Frame Duration $> 1.5 \times T$）严格 $< 1.0$ 帧 / 千帧。

### 4) 对 DRAFT G1/G2 的 LOCK 粘贴句

* **G1/G2 粘贴句 1**：“性能 CI 验收必须在 $\ge 2$ 台独立的物理机上执行（单机或虚拟机直接判为 INVALID），每台机器须运行包括闲置、平稳播放和打断重定向在内的 3 个标准场景，每场景采集 $\ge 1000$ 帧且独立进程运行 $\ge 2$ 轮。”
* **G1/G2 粘贴句 2**：“P95 指标须同时满足绝对预算上限（UI/渲染/GPU 分别对应刷新间隔 $T$ 的 $12\%/35\%/35\%$）与相对本机基线回退 $\le 10\%$ 的回退门禁，P99 每千帧丢帧率须 $< 1.0$ 帧。”
