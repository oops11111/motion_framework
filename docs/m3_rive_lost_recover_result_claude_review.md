## 恢复过程（stderr，6 次完全一致）
1. 渲染线程检测到 `0x887A0005`。
2. 第 1 次尝试：`DXGI_ERROR_NOT_FOUND`（`0x887A0002`），此时**没有任何硬件适配器**，驱动还在重启。这正是 r2 abort 的原因：r2 没有这一步检查，在不可用的设备上直接建 Rive 对象。
3. 第 2 次尝试：在 RX 7800 XT 上建设备成功（每次的 LUID 都不同，说明驱动重启后适配器是新的实例）。
4. 再经过 500 ms 稳定期，第 4–7 次尝试交给 Rive，恢复成功。没有被拒绝的候选设备，SEH 捕获 0 次，没有 abort。

时间分布：最后一帧到检测约 2.3 s（驱动卸载，期间合成器不出帧），检测到恢复约 2.1–2.3 s，其中大部分在等适配器重新出现，我们自己的 500 ms 稳定期约占四分之一。

## 新发现：应用自己的 XAML 界面在驱动重启后没有恢复（重要，不在本票判据内）
- 三个会话、每次注入后的截图（seg1、seg2）里，**窗口里所有 XAML 内容都消失了**：页面标题、开关、按钮、探针的提示文字，连标题栏的图标和标题文字也没了。只剩深色背景，以及我们自己的 Rive 视觉（它画得正确）。
- 像素统计：标题区亮像素 seg0 = 1518，seg1/seg2 = 0；提示文字区 506 → 0，三个会话完全一致。探针在恢复后**改过**提示文字（“第 1 段 …”），也没有画出来，说明不是“旧内容丢了还没重画”，而是 XAML 之后就不再出画面了。
- 我们的代码只对**自己的** `CompositionGraphicsDevice` 调了 `SetRenderingDevice`，没有碰 XAML 的设备，所以更可能是 WinUI 3（WinAppSDK 2.5.1，unpackaged + self-contained，Windows build 26300）本身在驱动重启后没有恢复 XAML 渲染。**这一点还没证实。**
- 影响：如果属实，任何 WinUI 3 宿主应用在驱动更新或重启后都会“只剩 Rive 动画、界面全空”，这会挡住试点接入。建议下一张票先做**对照**：不启动 Rive（普通 MotionSoftDemo），同样重启一次驱动，看 XAML 是否恢复；再看等待更久、缩放窗口或最小化再还原能否让 XAML 重画。

## 其他
- 恢复耗时 2.1–2.3 s，主要由驱动重启决定，我们能压缩的只有 500 ms 稳定期（产品化时可改为更短，或在稳定期内先画上一帧的缓存）。
- K6：恢复后动画从头播放（截图里骑士姿态回到起始帧），符合裁决。
- Rive 补丁（`VERIFY_OK` 不应 abort）仍列 WP1 产品化待办：本票通过靠的是“不在坏设备上调 Rive”，不是 Rive 本身能容错。
