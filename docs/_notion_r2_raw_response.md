## A. R-2 裁决草稿

**建议：选 1 + 5。** R-2 记为 known-fail，§4 门槛不改；同时把 seedLead 默认值和两种对齐方式写进文档。不放宽门槛（2），不把重拟合 τ 当验收（3）。hybrid B（4）记为"已触发、延后评估"。

**理由**

1. **R-2 主要是 R-1 在打断点上的表现，不是 seed 逻辑的 bug。**
    - seedLead 从 0 ms 改到 16.7 ms，|Δpos| 从 27.612 降到 20.093（约 −27%），|Δvel| 从 183.0 降到 156.4（约 −15%）。但 postRMS 基本没动（178.91 → 179.66）。
    - 这说明调 seed 时序只改善了打断瞬间这一个点，打断后整段轨迹的误差没变。这个误差由形状决定，和 R-1 的固有残差 12–28%·travel 同源。
    - 和门槛比：位置超出约 40–55 倍，速度超出约 8 倍。差这么多，不像是一帧对齐或 seed 精度的问题。
    - #30 测得底噪约 0.5–0.7%，说明测量本身是可靠的，结果为真。
2. **不放宽 §4。** §4 的作用是抓 seed/打断逻辑的错误（量级 ≤0.5 px）。如果为了让 R-1 的残差能过而把门槛抬到 20–30 px 或 ≥15% 帧位移，就再也看不出 seed 误差，门槛等于作废。这和 R-1"≤1%·travel 不放宽"的原则一致。
3. **不把打断后重拟合 τ 作为验收。**
    - 重拟合会把 δ（seed 误差）吸收进新的 τ，正好吞掉要测的东西。而且"全程单一 τ"是约束，验收必须报单 τ 指标。
    - 和 #11–#12"已过"可以对上：那两项验证的是在 R-1 形状残差不参与的条件下（同一形状自洽），seed/打断逻辑本身是对的。#25 换成产品映射对照 spring.h，失败是形状引入的。二者不冲突，#11–#12 的结论保留。
    - 可以加一项**诊断指标**（不是验收）：用"打断时刻 Δ 减去同一时刻不打断时的 R-1 基线残差"得到增量 Δ。增量 Δ ≈ 0 就证明 R-2 完全由 R-1 解释。如果增量 Δ 明显 >0.5 px，就说明 seed 另有问题，R-2 要重开。
4. **hybrid B：触发条件形式上已满足（轨迹不达标），但 M1b 内不做。** 原因是它会动 composition.h / S1 映射，违反本轮约束。建议登记为"已触发，M1b 冻结后做纸面评估（不改代码）"。
5. **seedLead 默认保持 0 ms。** 16.7 ms 只改善单点指标，postRMS 略差，收益不稳定，不值得改变默认行为。文档写清两种对齐（打断帧对齐 / 提前一帧对齐）及 #25 的实测数字，供以后参考。

**对 M1b 的影响**

- 不阻塞 M1b。默认仍是显式 seed；产品映射和 composition.h 都不改。
- 验收报告必须列出单 τ 的 |Δpos| / |Δvel| / postRMS，并标注 `R-2 known-fail（R-1 衍生）`。
- 开放风险：真机打断时有明显的位置/速度跳变，量级约 20–28 px、约 150–180 单位/s。用户能感知到，需要在发布说明里提一下。
- 唯一会重开 R-2 的条件：增量 Δ 诊断显示 >0.5 px。
