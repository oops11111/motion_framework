## 解读
- **节奏**：渲染线程在每块屏上严格按该屏刷新出帧，偏差 P95 不到 0.2 ms，与 r1、r3 一样好。
- **GPU**：在垂直同步之后推迟 0.3·T 再提交，180 Hz 屏上 Rive 渲染段的 GPU 时间回到 0.040·T（约 0.22 ms），与 MATRIX 用 `DwmFlush` 时相同，说明 r3 的约一帧确实是“提交时刻撞上 DWM 合成而排队”，不是我们的工作量。r3 复核中的推断由此得到旁证（仍未用 GPU 跟踪工具直接证实）。
- **偏移本身**：高精度定时器实际等待比设定略长（0.30→0.32–0.39·T，约多 0.1–0.4 ms），在 180 Hz 屏上留下约 3.4 ms 给渲染和提交，Rive 实际只需约 0.2 ms CPU+GPU，余量充足。
- **延迟**：新帧在垂直同步后约 0.3·T 提交，由 DWM 下一次合成取走；相比 r3（排队约一帧），高刷屏上的额外延迟消失。

## 对框架的意义
混合刷新率下，Rive 渲染线程应**按窗口所在屏的垂直同步出帧，并在垂直同步后约 0.3·T 再提交**（`m0r_set_pacing_window` + 默认偏移 0.3）。这条应写进 WP1 的 Rive 宿主产品化（作为多屏时的默认节奏），默认值是否改为开启由 pidan 决定。
