# M2 并行下一票方案对比（PERF-CI HOLD · 仅文档）

### 1. Δv 绝对门

- **目标**：为动效重定向（Retarget）接口定义并实现明确的速度差（$\Delta v$）绝对触发门槛。
- **为何不依赖 ≥2 物理机**：属于单机纯逻辑与算法数学阈值限定，无需多机对比。
- **建议闸门 3–5 条**：
  1. 必须在 `MotionSystem` 控制器层引入 $\Delta v$ 阈值校验函数。
  2. 当新旧速度差低于绝对门槛值时，跳过重定向插值并直接合并，防止高频抖动。
  3. PASS/FAIL 判据：在单机单元测试中，$\Delta v$ 小于阈值时调用 `Retarget` 不引发数值突变即为 PASS。
- **与 M2-02 / H5 产物衔接**：直接复用 M2-02 的 `Retarget` API 与 `FluidMotion-Motion` 事件流追踪速度变化。
- **风险**：无风险触及 `composition.h` 或影子 IV；不与 PERF-CI HOLD 冲突。

### 2. L 偏高

- **目标**：定位并压缩 A/B 方案间的延迟/响应耗时差距（优化 B 侧 40–45 ms 偏高问题向 A 侧 20–29 ms 靠拢）。
- **为何不依赖 ≥2 物理机**：可在单机 `DESKTOP-K93N3P8` 上借助现有工具链直接定位瓶颈。
- **建议闸门 3–5 条**：
  1. 利用 ETW Provider `FluidMotion-Motion` 对 B 路径各阶段耗时进行单机 Profiling。
  2. 识别并消除不必要的线程上下文切换或内存分配。
  3. PASS/FAIL 判据：单机 P95 延迟较基线降低 $\ge 20\%$ 且不恶化丢帧率即为 PASS。
- **与 M2-02 / H5 产物衔接**：复用 M2-02 已冻结的 PresentStats 与 ETW 追踪能力。
- **风险**：不触及 `composition.h` 与影子 IV；属于高层性能调优。

### 3. 单机多刷新率（单机矩阵，非双机 PERF-CI）

- **目标**：在单台物理机上通过虚拟/驱动或系统设置（如 60Hz / 120Hz 切换）验证引擎在不同刷新率下的时间步长自适应能力。
- **为何不依赖 ≥2 物理机**：单机通过多档位刷新率切换即可完成矩阵验证。
- **建议闸门 3–5 条**：
  1. 编写多刷新率下时间步长 `dt` 动态计算的回归测试。
  2. 验证在 60Hz、120Hz 下弹簧收敛曲线无数值发散。
  3. PASS/FAIL 判据：各刷新率档位下通过单机自动化测试且无时间戳跳变即为 PASS。
- **与 M2-02 / H5 产物衔接**：复用预览宿主 v0 与 WGC 稳定 seed 机制。
- **风险**：不触及 `composition.h`；不涉及双机 PERF-CI 闸门冲突。

- **建议闸门 3–5 条**：
  1. 在 seed 采样层实现轻量级指数平滑或滑动窗口滤波。

  3. PASS/FAIL 判据：静止或匀速输入下速度标准差下降 $\ge 30\%$ 即为 PASS。
