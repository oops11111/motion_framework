## 结论：FAIL 成立，原因明确
| 判据 | 结果 |
|---|---|
| ① 节奏 | **不满足**：渲染循环间隔 P50 在**两块屏上都是约 5.6 ms**（≈ 178 Hz）。在 180 Hz 屏上正确（P50/T = 1.01–1.02，超长间隔 0.07–0.63%）；在 75 Hz 屏上 P50/T = 0.42，即每秒画约 178 帧给 75 Hz 的屏 |
| ② 稳定 | 满足：每段约 1440 帧，0 失败 |
| ③ 跨屏卡顿 | 满足：12 次跨屏最长间隔 7.1–11.6 ms（门槛 100 ms） |
| ④ 预算 | 满足：CPU P95 ≤ 0.118·T，GPU ≤ 0.041·T |
| ⑤ 尺寸 | 满足：100% 时 400 px，150% 时 600 px；缩放变化在拖动约 0.5 s 后、跳转后 13–17 ms 被捕获，重新光栅化 2.6–4.2 ms |
| ⑥ 清晰度 | 满足（截图中 Rive 画面清晰） |
| ⑦ 合成器（记录） | 每段 DComp 帧数约 1440 / 8 s = 180 Hz，帧周期原始值 55553（100 ns 单位 = 5.56 ms），**两块屏上都一样** |

**原因**：混合刷新率下，DWM 按最快的那块屏（180 Hz）合成；Rive 渲染线程用 `DwmFlush` 等“下一次合成”，所以无论窗口在哪块屏上都按 180 Hz 画。在 75 Hz 屏上这带来两点：每帧之间的动画步长与屏幕刷新不对齐（每次刷新前进 2 或 3 个渲染帧，节奏不均匀），以及约 2.4 倍的无用 CPU/GPU 开销。
