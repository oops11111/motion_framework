# M1b 规格：真实合成器单属性试点（WinUI 3 / Microsoft.UI.Composition）

状态：规格，未实现（修订 2：补充读值/测量方法）。事实分四级：**[文档]** 已在 Microsoft Learn 查到；**[实测]** workbuddy 试点结果；**[推断]** 我的推理，需实测；**[未验证]** 文档查不到或沉默。
已知基线：box g++ 与 MSVC 19.44 四套测试 422/743/236/2063 全过；Windows 软件路径打断连续性 13/0（原生 C-ABI，|Δv|=|Δvel|=0）。
**试点实测（影响本规格）：** 屏幕可能休眠；`CompositionPropertySet.TryGetScalar` 只返回静态值（全 0）；关键帧动画约 14–30 ms 就报告完成。

## 0. 范围

- 一个目标（一个 Border 的 Visual），每次一个属性：`opacity`（keyframe+bezier）、`offsetX`（spring、可打断）。
- 经 `composition.h` 的 `CompositionDispatcher` → 新增 C# `WinRtBackend`；软件路径保留作对照。
- **不做**：partialStart（elapsed>0）、rate≠1、reverse、loop、多轨同属性、chained stages（计划器会走 AppThread/Hold 回退）。
- **前置代码任务**（`composition.h` 目前没有这些开关）：`Capabilities` 增加 `partialStart / playbackRate / reverse`，试点后端全设 false，使 SetRate、暂停后恢复等场景落回 AppThread 而不是下发错误动画。
- 不宣称零 CPU：引擎仍需每帧 `Tick` 做完成记账（`Withdraw`、AppThread 值）。UI 线程卡死时合成器动画继续，引擎记账在解除后补上。
- **完成事件的风险：** 引擎按自己的时钟判完成，合成器按它自己的；若合成器动画被提前判定完成（见 §7.1 现象 B），画面会在十几毫秒内跳到终值，而引擎侧一切“正常”。因此 **M1b 一切通过判据以截帧为准，不以完成事件为准**。

## 2. 映射

### 2.1 弹簧

我们的模型：`x'' + 2ζω₀x' + ω₀²x = 0`，`ω₀ = 2π/T₀`，`T₀ = response`，`ζ = damping`。
stiffness/damping/mass 互换：`k = mω₀²`，`c = 2ζ√(km)`；反向 `ω₀=√(k/m)`，`ζ=c/(2√(km))`，`T₀=2π√(m/k)`。m=1 时 `k=(2π/T₀)²`，`c=4πζ/T₀`。

`ζ_c = ζ`（文档语义一致，仍以 M-1 校验）。`Period` 有三个互斥假设，**由实测二选一，`SpringMapping::ToCompositor` 只改这一处**：

| 假设 | 含义 | 换算 `P_c = ?` |
|---|---|---|
| H1（当前代码） | Period = 无阻尼固有周期 | `P_c = T₀` |
| H2 | Period = 阻尼周期（仅 ζ<1 有意义） | `P_c = T₀/√(1−ζ²)`；ζ≥1 需另行约定 |
| H3 | Period = `1/ω₀` | `P_c = T₀/(2π)` |

[推断] 文档推荐 Period=50 ms（ζ=0.8）：H1 下 T₀=50 ms（20 Hz，极硬）；H3 下 T₀≈314 ms，更像常见响应时间。文档自身又用 0.5 s，所以只能当线索，**不能当结论**。

**判别（两次捕获，用 §7 的截帧法）：**
- (a) ζ_c=0，P_c=0.4 s，0→1：理论 `x=1−cos ωt`，量测振荡周期 `T_m`，`k₀=T_m/P_c`。k₀≈1→H1，≈6.283→H3。
- (b) ζ_c=0.5，P_c=0.4 s：量测相邻波峰间隔 `T_d`。若 `T_d≈k₀P_c/√0.75` 则属无阻尼型（H1/H3）；若 `T_d≈P_c` 则属阻尼型（H2）。
- 对数衰减校验 ζ：`δ=ln(xₙ/xₙ₊₁)`，`ζ_eff=δ/√(4π²+δ²)`，与设置值比较。
- 初速度单位（S3）：ζ_c=1，设 `InitialVelocity=v₀`，量前 3 帧斜率，应为 v₀ 每**秒**。

调用（`SpringAnimation` 已是合成器参数，含 `SpringMapping`）：
```csharp
var a = compositor.CreateSpringScalarAnimation();
a.DampingRatio = (float)s.dampingRatio;
a.Period = TimeSpan.FromSeconds(s.period);
a.InitialValue = hybrid ? (float?)null : (float)s.from;   // 见 3.B
a.FinalValue = (float)s.target;
a.InitialVelocity = (float)s.fromVelocity;                // 每秒（S3 待测）
a.DelayTime = TimeSpan.Zero;                              // 试点只允许 0
visual.StartAnimation("Translation.X", a);                // 元素先 SetIsTranslationEnabled(el, true)
```
注意路径：默认 `StaticCapabilityProbe` 把 `offsetX` 映射为 `"Offset.X"`，对 XAML 元素大概率被布局覆盖，试点探针须映射为 `"Translation.X"`。

### 2.2 Bezier

`ScalarKeyFrameAnimation`：
- `Duration = TimeSpan.FromSeconds(spec.duration)`，`IterationCount=1`，`DelayTime=0`。**StartAnimation 前必须日志 `Duration.TotalMilliseconds` 与全部 progress**（见 §7.4）。
- 每个 `KeyframeSpec k`：`progress=(float)(k.time/spec.duration)`；首帧 progress=0 不带缓动；**末帧 progress 强制 1.0f**。
- 缓动：`k.bezier ? compositor.CreateCubicBezierEasingFunction(new Vector2(x1,y1), new Vector2(x2,y2)) : compositor.CreateLinearEasingFunction()`，作为**结束关键帧**的缓动传入 `InsertKeyFrame(progress, value, easing)`（K1，实测确认）。
- 控制点 y∉[0,1]：默认 `bezierOvershoot=false`；T-K2 通过后才放开。
- `StopAnimation(path)` 后属性是否留在当前值（K5）、完成后是否保持终值（K4）：实测。

## 3. 飞行中 retarget 不跳变

误差来源：引擎在调用时刻 t_c 算出 (值, 速度)，合成器实际显示的是提交时刻 t_c+δ（δ≤约 1 帧）。直接用引擎值重启弹簧，可见跳变约 `v·δ`（v=700/s、δ=8 ms 时 ≈5.6）。**读值不可行**（见下表 E，已被试点实测），所以两个方案都不依赖回读。

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **B 混合（推荐）** | 不设 `InitialValue`（文档：缺省=当前值）；`InitialVelocity` 用引擎速度；同一 UI 线程回合 `StartAnimation` 替换旧动画 | 位置对屏幕上实际值**天然连续** | 依赖“缺省=动画中的当前值，而非最后一次 UI 设置值”（T-C1 验证）；速度仍有 `a·δ` 量级误差 |
| **A 引擎播种+前瞻（后备）** | 设 `InitialValue/InitialVelocity` 为引擎在 `t_c+δ_est` 的值（旧弹簧解析式外推 δ_est≈1 帧） | 不依赖缺省行为；可数学补偿 | 需实测 δ_est；δ 抖动时残差仍在 |
| C 表达式/属性集跟随 | 动画驱动 PropertySet，Visual 用 ExpressionAnimation 跟随 | 可分离驱动与显示 | 连续性问题原样转移，复杂度高，不推荐 |
| D `InitialValueExpression` | `"this.StartingValue + Δ"` 表示相对终点 | 相对位移很方便 | 成员在 WASDK 2.5.1 未确认；不解决速度 |
| E 回读到 UI 线程 | `TryGetScalar` / 读 Visual 属性 | — | **[实测] `TryGetScalar` 恒静态；放弃。** 唯一已知推送通道见 §7.2 方法 2 |

**决策规则：** T-C1 通过用 B；不通过用 A（δ_est 取实测中位数）。两者都做 M-4，选 J 更小者。

**后端接口增量（C ABI，纯 blittable）：**

## 6. 风险与待办

- Period 语义与 InitialVelocity 单位文档沉默，只能实测；推荐值与示例相差 10 倍，勿据此取值。
- **屏幕休眠会使合成器帧率降低或停止，所有合成器测量作废**（G0）。软件路径结果不受影响（引擎自带时钟）。
- 完成事件与读值接口不可靠（§7.1），M1b 的通过判据只认截帧。
- 无头/无显示环境没有可靠方案（§7.2 末条）；自动化需要真实点亮的显示器。
- `Translation` 单位按 DIP/有效像素处理，需在 150% 缩放下实测。
- 对象释放：`CompositionAnimation`、缓动函数是 `IClosable`，替换/停止后何时 `Dispose` 安全，在 M-7 里一并验证。
- 可选后续：给 `MotionSystem` 加 `NextWakeTime()`，让完成记账靠一次性定时器而非每帧 Rendering。

## 7. 读取飞行中数值 / 测量合成器路径

### 7.1 两个现象与可能原因

**现象 A：`TryGetScalar` 只返回静态值（全 0）。**
- **最可能（设计如此）：** 属性集的值由 UI 侧 `InsertScalar` 写入；动画和表达式在合成器线程对合成器侧副本求值，**不回写**应用侧副本。文档只把属性集描述为存储与引用，没有承诺回读 [文档沉默]；实测与此一致。所以“全 0”就是你们插入的初值，**不能说明表达式有没有在跑**。
- 次要：表达式没启动、路径或参数名拼错、显示休眠时合成器不出帧，表现同样是 0，**无法单靠这个读数区分**。
- **判别：** 先 `InsertScalar("x", 7)` 再读，应读到 7（证明读的是应用侧）；同一个表达式再驱动一个可见元素（Opacity 或条形长度），用截帧看它是否真的在变。若在变而 `TryGetScalar` 仍为 0，即确认“合成器侧求值、无回写”。
- 结论：这不是 bug，不要用它做测量。

**现象 B：关键帧动画 14–30 ms 就报告完成。** 文档：动画批在“批内最长动画的 delay+duration 过去后”触发，所以 14–30 ms 约等于合成器 1–2 帧（32 fps 时即 1 帧）。按可能性排序：

| 编号 | 假设 | 判别实验 |
|---|---|---|
| B1 | **批里没有动画（空批），下一次提交即完成。** `StartAnimation` 在 `batch.End()` 之后调用；或批与动画不是同一个 `Compositor`；或 `StartAnimation` 因路径无效没有真正连接 | 打印 `IsActive/IsEnded`；把 `StartAnimation` 放在 `CreateScopedBatch` 与 `End()` 之间；用 3 s 的 `Opacity` 标定动画重测 |
| B2 | **有效 delay+duration 本身只有十几毫秒**：单位/赋值错（如 `FromMilliseconds` 传了秒数）、`Duration` 没设，或关键帧 progress 写成了秒而非 0–1 | `StartAnimation` 前日志 `Duration.TotalMilliseconds` 与全部 progress（首=0，末=1） |
| B3 | **路径无效：** `Translation.X` 但未调 `SetIsTranslationEnabled`，`StartAnimation` 不一定抛异常 | 改用 `Opacity` 标定，对比结果 |
| B4 | **合成器时间被推进：** 显示休眠/遮挡导致 DWM 暂停，恢复后首帧 elapsed≫duration，一帧走完。特征：完成发生在恢复后第一帧，延迟与动画时长无关 | 显示器点亮、窗口可见、前台时重跑；先做 §7.3 G0 |
| B5 | **测量方法自身粗：** 在 Rendering 里用 Stopwatch 读完成时刻，分辨率就是帧间隔（此前 31 ms） | 与截帧时间戳（`SystemRelativeTime`）交叉验证 |

B1–B3 是代码问题，B4 是环境问题，B5 是测量问题；先排 B2、B1（日志即可），再排 B4。

### 7.2 可靠读值/测量方法（按推荐度）

### 7.3 门禁 G0 与标定 E0（所有合成器测量之前必须通过）

**G0 环境门禁**（任一失败 → 本轮全部合成器数据作废）：
1. `DwmFlush()` 连续 300 次，平均间隔 = 1/刷新率 ±10%，p99 ≤ 1.5×；
2. `PresentMon` 对 `dwm.exe` 无长间隙；
3. 窗口可见、前台、显示器点亮。

**E0 标定动画**（已知答案）：被测元素上 `ScalarKeyFrameAnimation`，Duration=**2.000 s**，线性，0→300（`Translation.X`）和 0→1（`Opacity`）各一次。
- 截帧位置对时间线性拟合 R²≥0.999，斜率误差≤1%，起止时刻误差≤1 帧；
- `Batch.Completed` 时刻与截帧结束相差≤2 帧；
- 不通过 → 先按 §7.1 排 B1–B4，不得进入 M-1…M-9。

**E0b**：同一标定再跑一次 NaturalMotion（ζ=1，P=0.4 s），作为弹簧基线。

### 7.4 复现“14–30 ms 完成”：StartAnimation 前必须记录

`Duration(ms)`、`DelayTime`、`IterationCount`、全部关键帧 progress（首=0、末=1）、目标路径、`Visual` 是否已在树中、`batch.IsActive/IsEnded`（Create 后与 End 后各记一次）、批与动画是否同一个 `Compositor`、`StartAnimation` 是否抛异常、显示器是否点亮（G0 结果）。把这些与完成时刻一并写入日志，B1–B5 即可逐项排除。
