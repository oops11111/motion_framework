| 项 | 75 Hz 屏 | 180 Hz 屏 |

- **节奏**：与 r1 一样完美（`pacing_ok=1`，3/3）。
- **预算**：按 r3 定义（只看 Rive 渲染的 GPU 时间）仍然不过——**多出来的约一帧时间在“Rive 渲染”这一段里，而不是拷贝**。拷贝进表面只要 6–8 µs，没有在等 DWM。所以 r2 复核中“拷贝时等 DWM 读表面”的推断不成立，r3 的计时拆分把它排除了。

## 现在知道的事实
1. 同样的 Rive 工作，在 75 Hz 屏上 GPU 时间戳差 0.24 ms，在 180 Hz 屏上约 5.9 ms——**与该屏的一帧长度几乎相等**（1.05–1.08·T）。
2. 只在“垂直同步一到就开始画”时出现：MATRIX（`DwmFlush` 节奏，即在合成完成后画）同一块 180 Hz 屏上是 0.041·T。
3. 帧节奏不受影响：每个垂直同步一帧，0 超长间隔；CPU 也在预算内。
4. GPU 时间戳差反映的是 GPU 执行到这两个时间戳的时刻之差，**包含排队等待**，不等于 GPU 实际在做我们的工作的时间。

## 推断（未证实）
在 180 Hz 屏的垂直同步时刻，GPU 正在执行 DWM 的合成，而且 DWM 的工作里可能包含等待下一次翻转（flip）的步骤。我们在这个时刻提交的 Rive 渲染排在它后面，于是要等到下一个垂直同步附近才执行完——表现为约一帧的“GPU 时间”。在 75 Hz 屏上，DWM 按 180 Hz 的时钟合成，75 Hz 的垂直同步多数时候不与它重合，所以不排队。要证实需要在执行机上用 GPUView / PIX 看 GPU 队列，这是新的工作量。

## 影响
- 用户可见：在 180 Hz 屏上，每帧画面可能晚约一帧（5.6 ms）上屏；帧率和节奏不受影响。
- 资源：GPU 实际负载并没有增加（Rive 工作量不变）。
