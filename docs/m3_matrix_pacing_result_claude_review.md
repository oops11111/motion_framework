## 为什么 180 Hz 屏上 GPU 时间变长（分析，未证实）
- GPU 时间是一帧命令前后两个时间戳之差，包含 GPU 上的**等待**，不只是 Rive 的实际工作（Rive 本身约 0.2 ms）。
- 现在渲染线程在**垂直同步一到就开始画**，而 DWM 也恰好在垂直同步时开始合成、读取我们的绘制表面。我们把新帧拷进同一张表面时，GPU 要等 DWM 读完——等待约一整帧，所以时间差约 1.06·T。
- 在 75 Hz 屏上，DWM 按 180 Hz 的节奏合成，和 75 Hz 的垂直同步不重合，所以没有这个冲突（0.011·T）。以前用 `DwmFlush` 时，渲染线程总是在“合成刚结束”之后画，也没有冲突。
- 实际后果：GPU 负载并没有变大，但在 180 Hz 屏上新帧可能晚一次合成才上屏（多约 5.6 ms 的延迟）。帧节奏本身没有受影响（间隔 P95 5.65 ms，0 超长）。

## 建议的修法（r2）
**先等窗口所在屏的垂直同步，再等下一次合成（`WaitForVBlank` 之后 `DwmFlush`），然后才画。**
- 在 180 Hz 屏上，这就回到 MATRIX 的时机（合成之后画，不冲突），同时仍保证每个垂直同步只出一帧；
- 在 75 Hz 屏上，垂直同步之后最多再等一次 180 Hz 合成（≤ 5.6 ms）就画，仍然每个垂直同步一帧，节奏不变；
- 改动很小（`WaitFrame` 里多一步），其余测量不变。用同一套 PACING 判据（包括 ④）再测一次。
