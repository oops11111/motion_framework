--- 项目一句话 ---
Windows 桌面端动效框架（FluidMotion）：为 WinUI 3 提供合成器驱动的过渡/微交互，可打断且保留速度；设计侧经 Figma motion tokens / Rive；首发宿主 WinUI 3。

--- 架构（出处：summary.md / plan.md） ---
- 执行层：WinUI 3 / Windows.UI.Composition；常规过渡在 DWM 合成线程跑。
- 引擎：C++/WinRT，对外 WinMD → C#；不用 Rust；公开接口不混 C ABI（Rive/Skia 内部边界除外）。
- 动画模型：声明式时间线；三次贝塞尔 + 命名缓动 token；闭式解弹簧，改目标保留速度；默认可打断。
- 复杂矢量：Rive → CompositionDrawingSurface，表面位移/缩放/淡入由合成器属性驱动。
- 设计到代码：Figma 插件产 JSON motion tokens；热重载预览；CI 校验 token；黄金帧回归。
- 宿主：主接口 GetCompositionVisual()；首发附不被支持的 HWND 参考示例；EmbedToHwnd 推迟 V1.5（disputes.md）。
- 备选：若 Rive/D3D 验证失败 → Skia + swapchain（token/引擎不变）。

- 软件路径：MotionSoftDemo（WinUI3 / WASDK 2.5.1）已 build+启动；假 Tick / 后接真实 C-ABI（workbuddy_soft_demo.md）。
- 弹簧 Period 定案：Period = response（无阻尼周期 UNDAMPED）；DampingRatio = ζ。证据：response=0.32s、ζ=0.78 时峰峰≈0.511s（workbuddy_soft_demo.md / deepseek_m1b_spec.md 亮屏复测）。不要用 Period=response/√(1−ζ²)。
- 弹簧 NaturalMotion：TryGetAnimationController 对 NaturalMotion（弹簧）恒为 null；AnimationController 仅适用于 KeyFrameAnimation → 不能靠 PlaybackRate；rate 折进 Period 与 InitialVelocity（已真机核实）。
- 亮屏：DwmFlush / 合成 ≈60Hz vsync；但 UI 线程 CompositionTarget.Rendering 仍约 p50≈31ms（~32Hz）——属 UI 节流，非熄屏问题；软件路径物理积分应用引擎稳态时钟（workbuddy_soft_demo.md 派题 #9）。
- offsetX/Y：XAML 元素须 Translation.X/Y + SetIsTranslationEnabled（Offset 会被布局覆盖）。
- Claude M1b：单属性试点（opacity keyframe+bezier；offsetX spring 可打断）；Capabilities 需关掉未支持的 partialStart/rate/reverse。
