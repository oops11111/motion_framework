## 解释
- **Rive 表面里的内容比合成器驱动的 visual 晚约 2 帧，原因不在 UI 线程。** B 绕过了 UI 线程，却几乎没有改善（约 2 ms），说明 A 的多出的约 25 ms 来自绘制表面这条管线本身：渲染线程在 `DwmFlush` 返回后画一帧，`BeginDraw/EndDraw` 提交，要等后面的合成帧才上屏；而表达式驱动的 visual 在下一次合成时就直接取到新的指针位置。
- **所以“渲染线程最后时刻读光标”在当前的渲染节奏下没有意义**：读的时刻已经是 `DwmFlush` 刚返回，和 UI 线程送来的位置差不多新。要缩短表面内的延迟，需要让渲染更贴近合成截止时间，或改走交换链路径（F1 中的可选路径），这属于新的测量，不在本票。
- **接缝方向**：拆出的部件**领先** Rive 里的其余内容约 2 帧（26 ms）。按测试里的拖动速度（120 px / 300 ms = 0.4 px/ms）约 10 px；快速拖动（约 1.2 px/ms）时约 31 px，肉眼可见。

## WP2 设计约束（建议写入，供 pidan 采用）
1. **默认做法**：跟随指针、并且对跟手感敏感的部件（光标附近的装饰、高光、被拖动的把手），拆成独立的合成器 visual，用指针属性集的表达式驱动。比留在 Rive 里快约 2 帧（75 Hz 下约 25 ms）。
2. **接缝**：拆出的部件会领先 Rive 里的其余内容约 2 帧。所以：
   - 只拆“和 Rive 主体松耦合”的部件（装饰性跟随、拖尾、光晕）；
   - 拆出的部件加轻微弹簧阻尼（时间常数约 2 帧），掩盖与 Rive 主体的错位（disputes §3）；
   - 必须和 Rive 主体严格对齐的部件（例如角色的眼睛跟随光标），**留在 Rive 里**，接受约 65 ms 的跟随延迟。
3. **不采用**“渲染线程最后时刻读光标”作为表面内的默认做法（收益 < 0.2 帧）。
4. **后续可测**：表面内延迟的根因在渲染节奏；如需缩短，另开票测量“贴近合成截止时间渲染”或交换链路径。
5. 以上数字来自 75 Hz、单显示器；60 / 144 Hz 和混合刷新率在 M3-MATRIX 中复核。
