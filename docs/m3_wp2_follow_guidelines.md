# WP2 指针跟随设计约束（m3_wp2_follow_guidelines.md）

> 状态：**已采用**（pidan T1，2026-11-02）。依据：M3-RIVE-FOLLOW 真机结果（`docs/m3_rive_follow_result.md`、`docs/m3_rive_follow_result_claude_review.md`），DESKTOP-IJI1KJG，75 Hz（T = 13.33 ms），单显示器，缩放 100%。60 / 144 Hz 与混合刷新率由 M3-MATRIX 复核后补充。
> 适用：用本框架在 WinUI 3 宿主中放置 Rive 动效、且有部件需要跟随指针的设计和实现。

## 1. 实测数据（指针移动 → 屏幕反映）
| 做法 | 延迟 P50 | 相对“留在 Rive 里” |
|---|---|---|
| 部件留在 Rive 表面里（Rive 内部响应指针） | 约 65 ms | 基准 |
| 留在 Rive 里，但渲染线程每帧自己读光标 | 约 64 ms | 快 0.1–0.2 帧（可忽略） |
| **拆成独立合成器 visual，由指针表达式驱动** | **约 41 ms** | **快约 2 帧（约 25 ms）** |
| 拆成独立 visual，由 UI 线程写位置 | 约 54 ms | 快约 0.8 帧 |

拆出的部件与仍在 Rive 里的内容同时跟随时，拆出的部件**领先约 2 帧（约 26 ms）**；慢速拖动约 10 px，快速拖动约 30 px 的错位。

## 2. 约束
1. **对跟手感敏感、且与 Rive 主体松耦合的部件，拆成独立的合成器 visual，用指针属性集的 ExpressionAnimation 驱动。** 典型：光标附近的光晕、高光、拖尾、被拖动的把手。
2. **拆出的部件要加轻微弹簧阻尼**（时间常数约 2 帧，75 Hz 下约 25–30 ms），掩盖它领先 Rive 主体的约 2 帧。
3. **必须与 Rive 主体严格对齐的部件留在 Rive 里**（例如角色眼睛看向光标、贴在角色身上的装饰），接受约 65 ms 的跟随延迟。设计时不要让这类部件承担“紧跟光标”的职责。
4. **不要用 UI 线程写位置的方式做跟随**（比表达式慢约 1 帧，且受 UI 线程负载影响）。
5. **不采用“渲染线程最后时刻读光标”作为默认**（收益 < 0.2 帧）。
6. 表达式路径依赖 XAML 宿主的 `GetPointerPositionPropertySet`；精简 HWND 宿主中不可用（disputes §3），HWND 宿主场景另议。

## 3. 背景（为什么表面内慢）
Rive 内容在独立的渲染线程上画进合成绘制表面，提交后要等后续的合成帧才上屏；表达式驱动的 visual 在下一次合成时直接取最新的指针位置。多出的约 2 帧来自这条表面管线，而不是 UI 线程转交——所以绕过 UI 线程（第 1 节第 2 行）几乎没有改善。要缩短表面内的延迟，需要改变渲染节奏（更贴近合成截止时间）或改走交换链路径，留作后续测量。
